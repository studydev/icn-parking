# Handoff: ICN 주차 네이티브 앱 (iOS · Android)

## Overview
인천공항 T1·T2 주차장 19개 구역의 **실시간 남은 면수/점유율, 3시간 예측, 7·14·30일 히스토리, 공항 셔틀 도착 예정**을 보여 주는 비공식 앱. 기존 웹(`studydev/icn-parking`, icn.igotobook.com)과 **같은 공개 데이터 파일**을 읽고, 예측·셔틀 계산은 웹과 같은 규칙을 앱 안에서 수행합니다. **서버 API 추가 없음.**

## About the Design Files
이 폴더의 `ICN Parking App v5.dc.html`은 **HTML로 만든 디자인 레퍼런스**입니다. 그대로 배포할 코드가 아니라, 보이는 모습과 동작을 **SwiftUI(iOS 17+)와 Jetpack Compose·Material 3(minSdk 26)로 다시 구현**하기 위한 기준입니다. 브라우저에서 열면(같은 폴더의 `support.js`, `data/shuttle.json` 필요) 상단 5a(iOS)·5b(Android)가 실제로 눌러 볼 수 있는 인터랙티브 화면이고, 나머지 5c~5s는 상태별 고정 화면입니다.

## Fidelity
**High-fidelity.** 색·글자 크기·간격·상태 표현이 최종값입니다. 아이콘만 자리표시(SVG 선 아이콘) → iOS는 SF Symbols, Android는 Material Symbols로 교체.

## 데이터 (기존 공개 파일만 사용)
기준 URL = 웹 배포의 `DATA_BASE_URL`(웹 `config.js`의 `dataBase`). 모두 gzip JSON. 형식은 저장소 `docs/DATA.md`.

| 파일 | 캐시 | 앱에서 쓰는 곳 |
|---|---|---|
| `latest.json` | 60초 | 실시간 탭 현재값(`zones[].p`·`c`·`flags`), 기준 시각(`slot`), `stale`/`ok` → 상단 줄 상태 |
| `days/YYYY-MM-DD.json` | 과거 1일 · 당일 60초 | 예측(지난 1~4주 같은 요일 흐름), 상세 시트 그래프, 히스토리 7/14/30일 |
| `calendar.json` | 60초 | 존재하는 날짜(`days`), 공휴일(`holidays`) → 히스토리 빨간 날 |
| `shuttle.json` | 앱 번들 | 셔틀 탭. 이 폴더 `data/shuttle.json` = 저장소 `web/shuttle.json`(2026-10-01 기준) 그대로. 시간표가 바뀌면 앱 업데이트 또는 웹 경로에서 원격 갱신(선택) |

- 구역 id·이름·순서: `functions/config/zones.yaml` (19개). 점유율 `p/c`, 남은 면수 `max(c-p,0)`, `c==0` = 운영 중단.
- `e`(보정 슬롯)는 그래프에는 그리되 통계·예측 기준점에서 제외(웹과 동일).
- 지난 날짜 파일은 디스크에 영구 캐시 → 30일 히스토리도 처음 한 번만 받음.

## 계산 규칙 (웹 코드에서 이식)
- **예측(예측 탭·상세 시트)** = `web/app.js`의 `forecastOf()` 오프셋 방식: 1~4주 전 같은 요일·시각의 주차 대수(±2슬롯 평균)에 "지금 대수 − 그때 대수"를 더하고 **현재 운영 면수**로 환산. 칸은 **지금 + 30분 간격 6칸(+30분~+3시간)**. 실패 사유 문구도 그대로(운영 중단 / 지금 값 없음 / 지난 4주 기록 없음 / 면수 변경 직후 `capacityPredictionIssue`).
- IGoTo(`web/forecast.js`)는 1차 범위 밖. 필요하면 같은 파일을 JS 엔진 없이 Swift/Kotlin으로 옮기고 `tests/forecast*.test.cjs` 값으로 검증.
- **셔틀** = `web/shuttle.js`의 `shPrep`/`shNext`: `"HH:MM"`(24시 이상 = 자정 후, 끝 `*` = 표시편) → 분. **지금(KST)보다 엄격히 뒤인 출발만**, 남은 분은 내림. 오늘 없으면 내일 첫차("내일 04:35"). 15초마다 다시 계산.
- **합계**: 터미널 전체 = 단기 + 장기·타워(예약 제외). 그룹 합계는 운영 중단·현재값 없는 구역 제외.

## Screens
공통 프레임: 상태바 → 헤더(50pt) → 상단 줄(30pt) → 본문(좌우 16) → 하단 탭(80pt). 서체 Pretendard(iOS 대안 SF Pro, Android 대안 시스템 산세리프), 숫자는 tabular.

**헤더** — 제목 20/700(-0.5) 왼쪽, 오른쪽에 `점유율 | 주차면` 토글, 그 오른쪽 `T1 | T2`. iOS: 회색 트랙(#eef0f3, r9, pad2) 안 선택 칸 흰색+그림자, 13/700, 높이 30, 좌우 10. Android: 외곽선 세그먼트 높이 34, 좌우 11, 선택 배경 tonal, 체크 표시 없음. 설정 탭에선 둘 다 숨김, 셔틀 탭에선 `T1|T2`만.

**상단 줄** — 높이 30, r9, 12.5/600 muted: 왼쪽 "14:30 기준 · 2분 전"(넘치면 말줄임) · 범례(여유 ▭36×6 만차, 11/600) · "↻ 새로고침". 지연("수집 18분 지연 · 14:12 기준")·오프라인("오프라인 · 14:28 저장본")일 때 이 줄만 warn 색(배경 warnBg, 글자 warnInk, 1px warnLine). 셔틀 탭에선 범례 숨김.

### 5. 셔틀 (5r, 5s)
- 노선 5칸 그리드(gap 4): 공항01~05, 높이 34, r10, 12.5/700, 앞에 7px 색 점. 선택 = 노선색 배경·흰 글자. 순서 T1: 01,02,03,04,05 / T2: 02,01,03,04,05. 터미널별 선택 노선·승강장은 기기에 저장.
- 노선 설명 12 muted: "{desc} · 배차 {headway} · {hours}".
- 카드(r16, 노선색 12% 연한 배경, 다크 30%): 승강장 이름 13/700 + 메모 11.5. **"N분 후"** 38/800 + "HH:MM 도착 예정", 옆에 그다음 차 20/700. ※ 표시편이면 warnInk "※ 이번 차는 {mark}". 맨 아래 "첫차 04:36 · 막차 23:48" 또는 "24시간 운행 · 심야엔 배차가 길어요".
- "정차 순서 · N개 승강장 / 다음 도착" 아래 목록(스크롤): 왼쪽 20pt 레일(2px 노선색 선, 12pt 원 — 선택은 채움), 이름 14(선택 800), 메모 11, 오른쪽 다음 도착 15/700("4분", "1시간 5분", 오늘 끝났으면 "내일 04:35" 12 muted). 행 높이 ≥46, 선택 행 배경 = 카드 색. 탭 = 그 승강장 선택. **열 때 선택 승강장으로 자동 스크롤.**
- 끝 줄: 순환 노선 "↻ {첫 승강장}(으)로 돌아와 순환 · 왕복 16분", 편도 노선 "… {after}". 맨 아래 "{as_of} 시간표 기준 · 실제 운행과 차이가 날 수 있어요".

## States (5a·5b 상단 버튼으로 전환)
정상 · 첫 로딩(회색 스켈레톤 + "최신 주차 정보를 불러오고 있어요") · 오프라인(마지막 저장본 + 상단 줄 warn) · 수집 지연(`stale` 또는 slot이 10분 이상 지남) · 구역 이상(운영 중단 `c==0`, 현재값 없음 `MISSING`, 면수 변경 `CAPCHANGE` → 예측 중지, 예측 불가).

## Accessibility
- 모든 칸 VoiceOver/TalkBack 문구: "단기 지하1층, 남은 40대", "15:00 예상 남은 120대, 지금보다 9대 감소", 셔틀 "공항01 장기탑승장 1, 4분 후 14:36 도착 예정".
- 색만으로 구분하지 않음: 단계 칩 문구, 만차/운영 중단 문구, ▲▼ 기호.
- Dynamic Type은 헤더·목록·설정만 확대(표·배치도는 고정 크기 + 접근성 문구).
