# IGoTo 예측과 미래 기간

## 구현 계획과 적용 범위

1. **현재 기준 연속 시간창:** 기본 상세 그래프는 현재 KST 시각의 **과거 72시간·향후 96시간**, 연속 7일입니다. 메뉴는 기존 이번 주 대신 **최근 3일**이며 2~4주는 과거 쪽에 7일씩 더 표시합니다. 미래는 **3·4일(기본)·5·7일**을 선택합니다. 예를 들어 2026-10-13 00:05에는 10월 10일 00:05부터 17일 00:05까지 보이므로 월요일이나 자정에 기록이 사라지지 않습니다. 수집 갱신은 기본 창만 이동하고 직접 확대/이동한 구간은 절대 시각을 유지합니다.
2. **기존 방식 보존:** 연결 예측은 선택한 비교 주의 흐름에 현재값 차이를 더하는 방식입니다. 면수 변동에 대응해 주차 차량 대수로 차이를 계산한 뒤 현재 운영 면수로 표시 지표를 변환합니다. 같은 면수·면수 이하 조건에서는 기존 계산과 같습니다. IGoTo는 별도의 켜기/끄기 옵션이며 기본으로 켜집니다.
3. **달력 조건 학습:** 공휴일·주말·연결 휴가 후보·연휴 전날 오후·연휴 직후를 구역별 실제 시간대 패턴과 함께 학습합니다. 고정 만차율을 더하거나 공휴일이면 무조건 만차로 만들지 않습니다.
4. **과거 시점 재현:** 브라우저와 검증 스크립트가 [같은 모델](../web/forecast.js)을 사용합니다. 각 검증 시점 뒤의 주차·면수 기록은 학습과 현재값 보정에서 제외합니다.
5. **검증과 공개:** 2026-10-01~11 스냅샷으로 오차·표본 수·실패 조건을 비교하고, 미래 기록이 아직 없는 조건은 한계를 명시합니다. 신규 Azure 리소스나 외부 예측 API를 만들지 않습니다.

## 연결 예측과 IGoTo 예측의 차이

| 항목 | 연결 예측 | IGoTo 예측 |
|---|---|---|
| 기준 | 선택한 1~4주 전 같은 시각 | 최근 최대 28일의 구역별 시간대·달력 조건 |
| 현재값 보정 | 현재와 비교 시각의 차이를 계속 더함 | 현재와 모델 값의 차이를 더하되 시간에 따라 감소 |
| 공휴일 차이 | 비교 주의 공휴일 패턴을 그대로 복사 | 대상 날짜의 공휴일·연결 휴가 조건으로 다시 계산 |
| 비교 주 기록이 없을 때 | 빈 예상선 | 유효한 주차 대수 실측이 2일·24시간 이상이면 학습 가능 |
| 표시 | 짧은 점선 | 긴 점선과 점의 조합, `IGoTo 예측` 범례·툴팁 |
| 성격 | 참고용 오프셋 예상 | 아직 짧은 연휴 표본으로 검증한 실험적 참고 예상 |

하단의 **지난 3시간 + 앞으로 6시간** 표는 기존 오프셋 방식입니다. IGoTo의 다일 예상은 위 그래프와 툴팁, 하단 개요 그래프에서 확인합니다. 실제 기록·예상·비교 주 기록은 서로 구분합니다.

표의 선택 지표는 점유율/가용 대수와 함께 바뀝니다. 과거 **주차 차량 대수**에 현재와 비교 시각의 대수 차이를 반영하고 현재 운영 면수로 변환합니다. 가용 대수는 0~현재 면수, 원 점유율은 100% 초과도 유지합니다. 각 구역의 요약은 현재 주차/전체 운영 면수·점유율이고, 셀은 선택 지표 하나만 표시합니다. 배경색은 두 모드 모두 점유율입니다. 아래 고정 예측·회고 집계는 변경하지 않습니다.

미래 범위 설명과 **IGoTo 예측 · 실험적 참고 예상**, 학습 표본·오류 안내는 6시간 예상 표 아래 **주차장 현황의 맨 하단**에 표시합니다. 상단의 선택 버튼과 그래프 사이에는 긴 설명을 두지 않습니다.

## 보존된 미래 예측 고정 기준(v1): 2026-10-11 12:00 KST

2026-10-11 당시 예측을 [고정 기준 자료](forecast-baseline-2026-10-11.json)로 보관합니다. 이는 **v1 모델의 역사적 기준**이며 10월 13일 면수 변동 대응 v2로 덮어쓰거나 이름을 바꾸지 않습니다. 미래 실측 비교 상태도 이 변경으로 임의 수정하지 않습니다.

| 기준 | 내용 |
|---|---|
| 수집 기준 시각 | **2026-10-11 12:00 KST** (`2026-10-11T03:00:00Z`) |
| 모델 | `IGoTo calendar ridge v1`, 해당 모델 파일의 SHA-256 기록 |
| 학습 범위 | 기준 시각까지의 최근 최대 28일, 이번 자료는 10월 1~11일 |
| 보관 대상 | T1/T2의 **19개 구역**, 기준 면수·학습 표본 수·관측 기준 슬롯 |
| 예측 범위 | 당일 13~23시와 **10월 12~18일의 매 정시**, 향후 7일 전체 |
| 값의 의미 | 화면의 100% 상한을 적용하지 않은 원 점유율, 배열 0=00:00~23=23:00 KST |
| 비교 상태 | `pending-actual-data` — 미래 실측 도착 전 |

고정 JSON은 당일의 이미 지난 시각과 기준 시각을 `null`로 남기고 미래 예상만 기록합니다. 미래 7일은 **19 × 7 × 24 = 3,192개** 정시 예상과 표본 부족 표시를 보관합니다. 원 관측 JSON·운영 주소·인증정보는 보관 자료에 복사하지 않으며, 사용한 날짜별 자료와 달력의 해시만 기록합니다.

### 12:00 기준 예상 요약

아래는 고정된 구역별 예상의 **면수 가중 장기·타워 합계**입니다. 예약주차장과 단기주차장은 이 요약에서 제외합니다. 100% 초과 표시 기준의 원 점유율을 소수점 한 자리로 요약했으며, 화면 기본 상한·표시 시각·개별 구역의 예상과는 구분합니다.

| 대상 시각 (KST) | T1 장기·타워 | T2 장기·타워 |
|---|---:|---:|
| 2026-10-12 12:00 | 88.6% | 88.5% |
| 2026-10-13 12:00 | 89.3% | 89.5% |
| 2026-10-14 12:00 | 89.5% | 89.8% |
| 2026-10-15 12:00 | 89.6% | 89.9% |
| 2026-10-16 12:00 | 89.7% | 90.0% |
| 2026-10-17 12:00 | 98.3% | 96.6% |
| 2026-10-18 12:00 | 98.3% | 96.6% |

이 값은 **당시 v1 모델의 참고 예상**이며 실측·주차 여유·만차 여부의 보장이 아닙니다. 연휴 종료 뒤 평일과 4~7일 뒤 예측의 검증 부족은 그대로 유지합니다. 운영 화면은 새 관측과 현재 모델로 다시 학습하므로 값이 달라질 수 있지만, 이 고정 기준 자료는 덮어쓰지 않습니다.

### 날짜가 지난 뒤 비교·보정하는 순서

1. **원 기준을 유지합니다.** 새 실측으로 모델을 다시 학습한 결과를 당시의 예측이라고 대체하지 않습니다. 추가 예측 기준은 시각을 달리한 별도 파일로 남깁니다.
2. 실제 날짜가 지나면 같은 구역·KST 정시 슬롯의 유효한 `p/c`를 받아 고정 예상과 짝지어 비교합니다. 아직 오지 않은 시각·누락·닫힌 구역은 제외하고 표본 수를 함께 기록합니다.
3. 면수가 기준과 달라진 슬롯은 별도로 집계합니다. 기존 모델이 같은 면수만 학습한 만큼, 면수 변경에 따른 오차를 휴일 예측의 오차와 섞지 않습니다.
4. **기본 3일(10월 12~14일)**과 **4~7일(10월 15~18일)**, T1/T2·장기/타워/단기/예약, 연휴 직후·일반 평일·주말을 나눠 MAE·RMSE·과대/과소 편향과 98% 이상 혼잡 감지 결과를 정리합니다. 화면의 100% 상한은 채점에 적용하지 않습니다.
5. 비교 결과는 이 문서에 후속 자료로 추가하되 고정 JSON과 기존 회고 검증 결과를 수정하지 않습니다. 표본이 충분히 쌓인 뒤에만 휴일 특징과 보정 계수 변경을 검토하고 변경 전후를 동일한 표본으로 비교합니다.

미래 비교 작업이나 자동 보정 작업을 예약하지 않습니다. 보존된 v1 기준은 날짜가 지난 뒤 실측 비교·보정의 근거로 별도 유지합니다.

### 새로운 고정 기준 자료 만들기

[스냅샷 명령](../scripts/snapshot-igoto.mjs)은 실행 시점의 모델 버전과 `latest.json`의 마지막 성공 시각을 기록합니다. v2 신규 출력은 기준 운영 면수·과거 관측 면수·예상 주차 대수·점유율·면수 유지 가정을 포함합니다. 파일 생성 시각을 예측 시각으로 쓰지 않으며 기존 출력 파일의 덮어쓰기를 거부합니다.

```bash
node scripts/snapshot-igoto.mjs SNAPSHOT /tmp/forecast-baseline-새기준시각.json
```

`SNAPSHOT`은 아래 검증 재현과 같은 로컬 자료 디렉터리입니다. 미래 실측이 파일에 들어 있어도 기준 시각 이후 슬롯은 학습에서 제외됩니다.

## 달력과 연결 휴가 후보

공휴일은 기존 [공개 달력](DATA.md#calendarjson)을 사용합니다. 공휴일 이름이나 휴일 날짜를 브라우저에서 임의 생성하지 않습니다.

- 먼저 주말·공휴일이 연속된 실제 휴일 구간을 찾습니다.
- 적어도 한 구간에 공휴일이 있고, 사이 평일에 **합계 최대 3일** 휴가를 쓰면 연결할 수 있는 구간을 묶습니다. 묶음 길이는 최대 16일입니다. 일반 주말이 반복된다는 이유만으로 황금연휴로 묶지 않습니다.
- 휴가를 내야 하는 평일은 **연결 휴가 후보**로 표시합니다. 실제 공휴일이나 모든 이용자가 휴가를 쓴 날로 취급하지 않습니다.
- 연휴 안 각 휴일 구간의 전날은 오후 12시부터 출국 수요 특징을 점차 반영하고 18시에 최대 특징값이 됩니다. 연휴가 시작되는 앞쪽 주말 전날도 포함합니다.
- 장기·타워에는 전체 연휴 종료 뒤 이틀간 감소하는 잔류 수요 특징을 추가합니다. 계수는 실제 자료에서 학습하며, 같은 조건의 자료가 없으면 임의 증가율을 만들지 않습니다.

**2026년 예시:** 10월 3일(토) 개천절, 5일(월) 대체공휴일과 9일(금) 한글날, 앞뒤 주말을 연결하면 **10월 3~11일, 9일**이 됩니다. 휴가 후보는 **6·7·8일, 3일**입니다. 10월 1일은 목요일이지 토요일이 아닙니다. 2일·8일 오후의 출국 수요를 별도 특징으로 구분합니다.

공휴일 달력이 현재/예측 연도를 포함하지 않으면 해당 예상은 비우고 이유를 표시합니다. 임시공휴일 등 변경 사항은 수집기에 전달되는 공식 달력 갱신을 따릅니다.

## 구역별 학습과 예측식

[모델](../web/forecast.js)은 바닐라 JavaScript의 작은 가중 ridge 회귀입니다. 추가 패키지·AI 호출·유료 계산 서비스가 없습니다.

1. 현재 KST 시각부터 최대 30분 안의 유효한 구역 관측을 기준점으로 삼습니다. 자정 직후에는 전날 마지막 슬롯도 확인합니다.
2. 최근 최대 28일을 시간 단위로 요약합니다. 시간당 최소 6개 유효 5분 슬롯이 있어야 하며, **예측 기준 시각까지의 슬롯만** 평균합니다.
3. **v2는 과거 주차 차량 대수 `p`를 현재 기준 운영 면수 `C`로 정규화(`p/C`)해 학습합니다.** 역사적 운영 면수가 달라도 유효한 차량 대수는 사용합니다. 누락·닫힌 구역·잘못된 값은 제외합니다. 최소 2개 날짜·24시간 자료가 없으면 이유를 표시하고 예상은 만들지 않습니다.
4. 특징은 상수항, 24시간/12시간 주기의 sin·cos, 실제 휴일, 공휴일 포함 연휴의 휴일, 연결 휴가 후보, 전날 오후, 장기·타워의 연휴 종료 후 잔류입니다.
5. 최근 자료의 가중치를 높이고 14일 간격으로 지수 감소시킵니다. 상수항을 제외한 ridge 정규화는 6입니다. 이 계수를 날짜·주차장별로 검증 결과에 맞춰 바꾸지 않습니다.

```text
모델 시간대·달력 값 = 학습한 계수 × 대상 시각의 특징
현재값 차이 = 최신 유효 주차 대수 / 기준 운영 면수 C − 기준 시각의 모델 값
IGoTo 예상 점유율 = max(0, 모델 시간대·달력 값 + 현재값 차이 × exp(−경과 시간 / τ))
예상 주차 대수 = IGoTo 예상 점유율 × C
예상 가용 대수 = max(C − 예상 주차 대수, 0)
τ = 장기·타워 24시간, 단기·예약 8시간
```

동일 분모 `C`를 사용하는 것은 수치적 정규화이며 목표는 실제 주차 수요입니다. 분모만 바뀌어도 주차 대수 예상은 바뀌지 않습니다. 모델은 100% 초과를 숨기지 않으며 상세 그래프에서만 기존 **100% 초과 표시** 옵션을 적용합니다. 모바일 초과 안내에는 실제 점유율을 표시합니다. 미래는 현재 운영 면수가 유지된다고 가정하며, 미공표된 미래 면수 변경을 미리 알거나 예측에 사용하지 않습니다. 실제 과거 그래프는 계속 각 슬롯의 원래 `p/c`, `max(c-p,0)`입니다.

모델 결과의 `limited`는 학습일이 7일 미만이거나, 같은 달력 조건을 2일 미만 관찰했거나, 전날 오후 조건을 2일 미만 관찰했거나, 72시간보다 먼 경우입니다. 또한 과거 면수가 여러 값이고 현재 면수 실측이 2일·24시간 미만인 변경 직후에는 **면수 변경 적응 중**임을 표시하되 과거 수요를 이용한 참고 예상을 계속 제공합니다. 확률·신뢰구간·만차 보장이 아니라 표본 부족 안내입니다.

## 운영 면수 변경 대응: 2026-10-13 v2

- T1 단기 지하1층의 기본 면수는 **378대**, 개천절·한글날 극성수기에는 **520대 임시 운영** 후 원복했다는 사용자 전화 확인 내용을 [별도 참고 메타데이터](../web/capacity.js)에 기록했습니다. 확인 경로는 일반 담당자가 아닌 **상황실(전화 끝자리 7700)**이며 전체 번호는 추정하지 않습니다. 공식 공개 공지로 확인한 원인이라고 표현하지 않습니다.
- API 수집 기록은 **2026-10-13 16:50에 주차 429 / 운영 520대**, **16:55에 주차 432 / 운영 378대**입니다. 16:55 원 점유율은 약 **114.3%**, 가용은 **0대**입니다. 면수 감소가 주차 차량의 즉시 감소를 의미하지 않습니다.
- 기본 378대는 API 현재 면수를 대체하지 않습니다. 향후 다시 면수가 늘거나 줄어도 같은 수요 학습·지표 변환을 사용합니다. 닫힘·누락·최신값/일별 파일의 갱신 중 불일치는 예측 불가 사유로 유지합니다.
- 날짜별 `c`의 변화를 모든 구역에서 감지하고 선택한 터미널·카테고리·보이는 구간의 상세/날짜/기간 타임라인과 하단 참고에 표시합니다. 자정 경계는 전날 마지막 관측과 비교합니다. 사유 미확인 이벤트는 수집 기준 첫 변경 시각·면수만 표시합니다.
- 감소 후 안정화 속도나 가용 대수가 생길 시각은 보장하지 않습니다. 모델 원 값·현재 초과 차량은 유지하고 가용 대수만 0 미만으로 내려가지 않게 합니다.
- v2 검증 스크립트는 미래 실제 면수가 예측 기준과 **같은/다른 목표를 분리**하고 점유율 오차와 주차 대수 MAE·RMSE를 함께 출력합니다. 미래 실제 `c`는 사후 평가 분류에만 쓰며 학습·예측 분모로 쓰지 않습니다. 특히 변경 전 시점에서 미공표된 원복을 모르는 점유율 오차를 수요 오차와 구분합니다.
- 아래 v1 회고 검증과 10월 11일 고정 기준은 그대로 보존합니다. 면수 변동 대응은 연휴 특징이나 정규화 강도·시간 감쇠 계수를 이번 사건에 맞춰 재조정한 결과가 아닙니다.

### v2 실측 확인: 2026-10-13 17:45 KST

## 2026-10-01~11 실측 회고 검증

[전체 집계와 스냅샷 해시](forecast-validation.json)는 **v1의 보존된 결과**이며 현재 v2 검증값으로 재표시하지 않습니다. 실제 기록 스냅샷의 마지막 성공 시각은 **2026-10-11 11:05 KST**입니다. 10월 1일은 구역별 238슬롯, 2~10일은 288슬롯, 11일은 134슬롯으로 하루가 아직 끝나지 않았습니다.

### 검증 규칙

- KST 00·06·12·18시를 예측 출발점으로 삼고, 각 시점까지의 관측만 학습합니다.
- 1~168시간 뒤의 정시 목표 가운데 스냅샷 시점에 실제 기록이 존재하는 목표만 비교합니다.
- 공휴일은 사전 공표된 달력이라고 가정하고 스냅샷 달력을 사용합니다. 과거 시점의 달력 변경 이력까지 검증한 것은 아닙니다.
- 오차는 표시 상한을 적용하지 않은 **원 `p/c`의 퍼센트포인트(%p)**입니다. 구역·예측 출발점·목표 시각별 표본을 동일하게 짝지어 비교합니다.
- SVG 평활화·보간·픽셀을 채점하지 않고 예측 수식의 원 시계열 값을 비교합니다.
- 비교 주차가 없는 경우 연결 방식의 값을 임의 생성하지 않습니다. 모델과 연결 방식이 **둘 다 가능한 9,975표본**의 결과를 별도로 집계합니다.
- 예측 출발점과 목표가 겹쳐 표본들이 서로 독립적이지 않습니다. 회고 검증이며, 별도의 다른 연휴·미래 평일에서 확보한 독립 테스트셋 결과는 아닙니다.

## 검증 재현과 테스트

운영 주소를 소스나 공개 문서에 넣지 말고, 자신의 공개 데이터 스냅샷을 로컬 디렉터리에 준비합니다. 원 자료는 커밋하지 않습니다.

```text
  latest.json
  calendar.json
  days/2026-10-01.json
  ...
  days/2026-10-11.json
```

```bash
node scripts/backtest-igoto.mjs \
  --data-directory SNAPSHOT \
  --from 2026-10-01 --to 2026-10-11 \
  --output /tmp/forecast-validation-v2.json
node --test tests/forecast.test.cjs tests/capacity.test.cjs tests/forecast-backtest.test.cjs tests/forecast-snapshot.test.cjs tests/app.test.cjs tests/build.test.cjs tests/deployment.test.cjs
```

현재 체크아웃의 모델 버전으로 실행하며 새 모델·데이터이면 결과도 바뀝니다. 보존된 v1 JSON을 v2 실행 결과로 덮어쓰지 않습니다. 원 자료의 날짜별 SHA-256은 집계 JSON에 기록되어 있습니다.

테스트는 미래 자료를 제공해도 학습 결과가 변하지 않는지, 일요일·자정·3/7일 전체 5분 슬롯·미래 구간 확대·툴팁·T1/T2·면수 변경·결측·연도 경계·100% 초과·가용 대수·기존 연결 방식을 확인합니다. 배포 검증은 실제 웹의 모델·대시보드 JavaScript가 검증한 소스와 일치하는지도 확인합니다.
