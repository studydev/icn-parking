# 사용 설명서

이 문서는 코드 실행과 기능 사용을 설명합니다. 클라우드 설치와 자동 배포는 [배포 설명서](DEPLOYMENT.md)를 참고하세요.

## 1. 실행 환경

- Python 3.12(수집기와 테스트)
- Node.js 20 이상(내장 테스트와 정적 빌드; Actions는 Node 22 사용)
- Git
- 실제 수집에 한해 공공데이터포털의 API 활용 신청과 Decoding 인증키

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r functions/requirements.txt pytest
npm ci --ignore-scripts
```

프런트엔드는 별도 라이브러리나 번들러 없이 바닐라 JavaScript와 SVG를 사용합니다.

## 2. 데모 실행

```bash
.venv/bin/python scripts/make_demo_data.py --out /tmp/parking-demo --days 40
.venv/bin/python scripts/serve_local.py --data /tmp/parking-demo/web/data --port 8080
```

`http://localhost:8080/`에서 확인합니다. 합성 데이터에는 시간대 변화와 장기주차장 면수 초과, 일부 누락을 포함합니다. 공식 실측으로 오인되지 않도록 데모 데이터는 운영 저장소에 올리지 마세요.

기본 `web/config.js`의 데이터 경로는 `./data/`입니다. 로컬 서버가 `/data/`를 지정한 데이터 디렉터리에 연결하고 gzip 응답도 처리합니다.

## 3. 실제 데이터 수집

1. 공공데이터포털에서 주차 현황·특일·승객 예고 API를 필요한 범위로 활용 신청합니다.
2. `.env.example`을 `.env`로 복사하고 `DATA_GO_KR_KEY`에 Decoding 키를 넣습니다.
3. 키와 원본 로그는 외부에 공유하거나 Git에 커밋하지 않습니다.

```bash
cp .env.example .env
# .env의 DATA_GO_KR_KEY를 편집
set -a
. ./.env
set +a

cd functions
LOCAL_DATA_DIR=../.localdata ../.venv/bin/python -c \
  'import os; from common.pipeline import run_collect; from common.store import stores_from_env; print(run_collect(*stores_from_env(), os.environ["DATA_GO_KR_KEY"]))'
cd ..
.venv/bin/python scripts/serve_local.py --data .localdata/web/data
```

위 호출은 한 번 수집합니다. 상시 5분 수집은 Azure timer Functions를 배포하거나 별도 스케줄러에서 같은 수집 파이프라인을 실행하세요. 매 호출은 현재값만 제공하므로 수집 시작 이전 기록을 소급 생성할 수 없습니다.

`scripts/local_collect.py`는 stdlib 기반 원본 수집 도구입니다. `--once`로 한 번만 실행할 수 있고, 저장된 원본은 `scripts/backfill.py`로 자체 Azure 저장소에 이관할 수 있습니다. 키는 환경변수 또는 로컬 `.env`에서 읽습니다.

## 4. 메뉴

### 주차장 현황

- **모바일 기본 보기:** 다른 메뉴와 같은 상단 **T1 제1터미널 / T2 제2터미널** 선택을 사용하며 **선택한 터미널**의 단기·장기(타워 포함) 개별 구역만 보여줍니다. 단기의 각 층, 장기 P1·P2·P3와 각 주차타워는 합치지 않습니다. T1은 단기 4·장기/타워 5, T2는 단기 5·장기/타워 3이며 예약주차장은 간단 보기에서 제외합니다.
- 상단 한 줄에 **11:20 · 11:40 · 12:00 …**처럼 20분 간격의 예측 시각을 한 번만 표시합니다. 현재 5분 슬롯에서 20·40·…·180분 뒤의 실제 시각이며 자정을 넘으면 `내일`을 표시합니다. 각 구역 이름 아래의 9칸 히트맵은 이 시각 순서를 공통으로 사용합니다. 숫자는 해당 구역의 예상 가용 대수이고 배경은 점유율입니다. 정확한 날짜·시간·점유율과 구역명은 툴팁·접근성 설명에도 남깁니다.
- 현재값은 **주차 가능 N대 / 전체 M대**로 표시합니다. 가능 대수는 구역별 `max(면수 − 주차 대수, 0)`이고 전체는 해당 구역의 총 면수입니다. 만차·면수 초과는 **0대**, 결측은 확인 필요, 수집 지연은 마지막 수집값임을 표시합니다. 닫힌 구역도 행을 남기고 운영 중단으로 안내합니다.
- 예상은 IGoTo를 사용하며 상세 화면의 카테고리·비교 주·예측 토글과 독립적입니다. 한 구역의 결측·면수 변경·예측 불가가 다른 구역을 숨기지 않으며 해당 구역에만 빈 히트맵과 이유를 표시합니다. 전체 수집이 지연되면 모든 미래 예상 숫자를 비웁니다. 예측식이나 면수 초과 표시 정책은 변경하지 않습니다.
- **상세 그래프**를 누르면 기존 주간 그래프·선택 설정을 사용할 수 있습니다. 데스크톱 기본은 기존 상세 보기입니다. 모바일 메뉴는 **주차 현황·날짜별·기간별·터미널 이동·안내·주차요금**을 한 줄에 모두 표시하며 별도의 더 보기 메뉴가 없습니다. 데스크톱 메뉴 이름은 기존대로 유지합니다.
- T1/T2를 선택합니다. 단기·장기(주차타워 포함)·예약 카테고리 상태는 터미널 전환에도 유지됩니다.
- 카테고리 선택은 해당 구역들의 선을 함께 켜거나 끕니다. 각 구역의 선은 별도로 유지됩니다.
- 기존 **이번 주** 대신 **최근 3일**을 기본으로 표시합니다. 현재 KST 5분 슬롯부터 **과거 72시간 + 향후 96시간(기본), 연속 7일**입니다. 월요일·자정에 기간을 끊지 않으므로 최근 실측과 다가오는 예상이 함께 보입니다. 2·3·4주는 과거 쪽에 각각 7·14·21일을 더 표시합니다.
- 미래는 **3·4일(기본)·5·7일**을 선택하며 현재 시각부터 해당 일수 뒤 같은 시각까지입니다. 새 시간창 기본값은 이전 주간 기본값과 별도로 저장됩니다. 기본 기간은 수집 갱신과 함께 이동하고, 사용자가 드래그 확대·이동한 구간은 날짜가 넘어가도 같은 절대 시각을 유지합니다. 오늘·지금 ±3시간도 제공합니다.
- 점유율과 가용 대수를 전환하면 그래프뿐 아니라 카드의 각 구역 값과 하단 참고 예상 셀도 `%` / `대`로 바뀝니다. 가용 대수의 배경색은 계속 점유율 기준입니다.
- 점선 비교의 1~4주 전 흐름은 실측선보다 옅게 표시합니다.
- 연결 예측을 켜면 선택한 비교 주의 값에 현재와 비교 시점의 차이를 더해 현재 그래프에서 앞으로 이어 그립니다.
- **IGoTo 예측**은 기본으로 켜지며 공휴일·주말·최대 3일의 연결 휴가 후보·연휴 전날 오후·연휴 직후를 구역별 최근 기록에서 학습합니다. 비교 주 선택과 독립적으로 켜거나 끌 수 있습니다.
- 미래 기간과 IGoTo 선택은 브라우저에 저장됩니다. 대상 기간의 5분 예상은 그래프·툴팁에서 보고, 개요 그래프로 미래 구간도 이동할 수 있습니다. 미래 실제값은 기록으로 채우지 않습니다.
- 아직 한 연휴 자료로 검증한 실험적 예상이며 일반 평일·4~7일 거리·예약주차장 등은 한계가 있습니다. [알고리즘과 실측 검증](FORECAST.md)을 확인하세요. 연결 휴가 후보는 실제 공휴일이나 모든 이용자의 휴가를 의미하지 않습니다.
- 미래 기간 설명과 **IGoTo 예측 · 실험적 참고 예상**, 학습·오류 안내는 그래프와 6시간 예상 표를 지난 주차장 현황의 맨 하단에 있습니다. 상단은 선택 버튼과 그래프 중심으로 유지합니다.

### 참고용 점유율·가용 대수 예상

직전 3시간의 실측과 현재, 이후 6시간의 정시 예상값을 표시합니다. 이 표는 기존 오프셋 방식으로 공휴일을 고려하지 않습니다. IGoTo의 다일 예상은 위 그래프에서 구분해 확인하세요.

```text
선택 지표 예상 = 과거 같은 요일·시각 값 + (현재값 - 과거 같은 시각 값)
```

같은 요일 기록은 지난주부터 찾고 없으면 2~4주 전으로 대체합니다. 기록이 없으면 빈 값/안내로 남기며 임의의 실측값을 만들지 않습니다. 이는 공식 예측 모델이나 실제 가용 면수 보장이 아닙니다.

각 구역의 왼쪽에는 **현재 주차 대수 / 전체 면수 · 점유율**만 요약합니다. 이전 주의 같은 시각·오프셋 설명은 빼고, 셀에는 선택한 점유율 또는 대수 한 값만 표시하여 행 높이를 줄였습니다. 실측/현재/예상 구분과 시각은 상단·툴팁·접근성 설명으로 유지하며 결측·예측 불가 이유도 남깁니다. 가용 대수 예상은 과거 가용 대수 흐름을 기준으로 계산하며 0~현재 기준 면수로 제한합니다.

구역명은 가로 이동 중에도 고정되고 날짜·00/06/12/18시 눈금으로 구간을 구분합니다. 마우스·터치로 정확한 날짜/시각 값, 키보드 화살표로 5분 단위 값을 확인합니다. 가용 대수 선택 시 조회 수치는 대수이며 색상은 점유율입니다. 아직 오지 않은 시각·수집 전은 빈 칸, 누락·미운영은 패턴으로 구분하고 보간하지 않습니다. 날짜·구역당 288픽셀 캔버스를 사용하므로 긴 기간에도 모든 5분 기록을 평균내지 않고 유지합니다.

앞으로 1년 이상 자료가 쌓이더라도 원 기록은 수집기에 계속 보관되며, 현재 조회 창은 최대 92일입니다. 조회 화면 변경만으로 예측 계수나 과거 예측 기준 자료를 보정하지 않습니다.

### 터미널 이동

노선 → 구역 → 승강장을 고르면 다음 두 출발·정차 순서·누적 소요시간·시간표를 함께 봅니다. 데이터는 정적 시간표이며 실시간 차량 위치가 아닙니다. 안내도는 실제 도로 축척을 재현하지 않습니다.

시간표가 변경되면 공식 자료를 확인해 `web/shuttle.json`의 정류장 시간·`as_of`·누적 소요시간을 함께 수정하세요. 공식 이미지는 파일로 재배포하지 않고 링크로만 연결합니다.

### 주차요금·감면·카드 계산기

상단의 **주차요금** 또는 하단 링크로 [요금 페이지](../web/fees.html)를 엽니다. 기본 화면에서는 주차장·터미널·입출차와 감면 한 가지·카드를 간단히 선택합니다. 다중 감면·차량 구분·사후환불·카드 실적 등은 필요할 때 상세 조건을 펼칩니다.

- 주차 현황에서 선택한 터미널을 요금 페이지의 초기 선택으로 전달하며, 요금 페이지의 메뉴 링크로 돌아갈 때도 해당 터미널을 유지합니다.
- 입력한 **입차·출차 KST 시각과 총 이용시간**을 확인한 뒤 **입출차 시간 확인 → 확인한 시간으로 요금 계산** 순서로 진행합니다. 시간을 바꾸면 이전 시간 확인과 결과는 무효화되며 다시 확인해야 합니다. 다른 옵션만 바꾸면 확인한 이용시간은 유지됩니다.
- 감면을 바꾸면 등록 상태를 `모름`으로 되돌립니다. 이전 자격의 등록 확인을 새 자격에 자동 적용하지 않습니다. 카드 상세 조건을 모두 누르지 않아도 미적용/조건 충족 시 시나리오로 계산할 수 있습니다.
- 모바일 결과는 **기본요금·정산 결제액·최종 부담 예상**을 먼저 보여주며 세부 감면/청구할인 내역과 요금표는 접어서 유지합니다.
- 기본요금, 공항 최고율 한 개의 감면액, 정산 결제액, 카드 승인액, 청구할인과 최종 부담을 구분합니다.
- 모르는 자격·실적·횟수·가맹점 조건은 모름으로 남겨 적용/미적용 시나리오를 봅니다. 전기차 선택만으로 등록 자격을 확정하지 않습니다.
- 사후감면은 정산 당시 금액을 유지하고, 승인될 경우 추가 환불과 카드 취소·혜택 환수 가능성을 별도로 표시합니다.
- 제공된 63,000원 사례는 계산기 버튼으로 입력 가정을 불러올 수 있습니다. 조건이 충족되는 가정에서 31,500원 정산·21,500원 최종 부담을 재현합니다.
- 무료시간·단기/화물 과금 경계와 일부 카드 적용 범위가 미확인이라 **조건부 예상**입니다. [요금 정책·검증](FEES.md)과 연결된 공식 자료를 참고하세요.

## 5. 100% 초과와 색상

- 메뉴 바로 아래 **우측의 공통 점유율 눈금**이 0~100% 색상과 만차 도달(98%+) 기준을 보여줍니다. 주차 현황·날짜별·기간별·터미널 이동·안내와 요금 페이지가 같은 눈금을 사용하며, 메뉴별 내용의 중복 색상 범례는 제거했습니다. 수집 누락 표시는 별도로 유지합니다.
- [공통 색상 함수](../web/occupancy.js)를 히트맵·달력·요약 막대·눈금이 함께 사용합니다. 기존 점유율 색상과 100% 상한 정책은 변경하지 않습니다. 요금 페이지의 눈금도 주차 **점유율** 기준이며 금액·할인율의 색상 기준이 아닙니다.
- 기본 점유율은 구역별 `min(주차, 면수) / 면수`로 계산합니다.
- `100% 초과 표시`를 켜면 실제 `주차 / 면수`를 사용합니다.
- 가용 대수는 항상 `max(면수 - 주차, 0)`입니다.
- 100% 이상 색상은 동일하게 유지합니다.
- 표시 상한은 UI 정책이며 원본 JSON 주차 대수는 변경하지 않습니다.

장기주차장에는 주차타워 진입 대기 차량이 함께 집계될 수 있습니다. 공식 면수/주차 대수의 의미는 제공 기관 안내를 함께 확인하세요.

## 6. 모바일/데스크톱 보기

화면 폭 700px 이하에서는 모바일 구성을 자동 선택합니다. 헤더의 전환 버튼으로 직접 선택하면 브라우저에 저장됩니다.

모바일 히트맵은 24시간 전체를 화면 폭에 맞추며, 터미널 이동의 대형 지도는 기본 접힘입니다. 휴대폰에서 데스크톱 보기를 선택하면 기존 넓은 화면을 가로 스크롤로 확인합니다.

## 7. 테스트

```bash
npm test
.venv/bin/python -m pytest -q tests
bash -n scripts/deploy.sh
```

테스트는 실제 API 키 없이 실행합니다. JSON 형식과 타임존·초과값·누락·중복·예상 오프셋·시간표·지도·모바일 모드·배포 설정 주입을 검증합니다.

공개 JSON을 자체 코드에서 사용하려면 [데이터 형식](DATA.md)을 확인하세요.
