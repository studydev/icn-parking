# 데이터 형식

이 저장소는 특정 운영 데이터 주소나 API 인증키를 포함하지 않습니다. 아래 URL의 `example`은 사용자가 배포한 저장소로 대체하세요.

```text
https://example.blob.core.windows.net/$web/data/
  latest.json
  calendar.json
  days/YYYY-MM-DD.json
```

파일은 `Content-Type: application/json`, `Content-Encoding: gzip`으로 제공됩니다. 브라우저 `fetch`, `requests`, `curl --compressed`처럼 gzip을 처리하는 클라이언트를 사용하세요.

## latest.json

| 필드 | 의미 |
|---|---|
| `v` | 스키마 버전(현재 1) |
| `generated_at` / `last_attempt_at` / `last_ok_at` | UTC 생성·시도·마지막 성공 시각 |
| `slot` | KST 5분 단위 슬롯 |
| `start` | 수집 시작 날짜 |
| `ok`, `error`, `stale` | 성공·실패·원천 갱신 지연 상태 |
| `zones[]` | 구역 메타데이터와 현재 주차 대수 |

구역:

```json
{
  "id": "t1-short-b1",
  "terminal": "T1",
  "category": "단기",
  "name": "단기 지하1층",
  "p": 300,
  "c": 520,
  "slot": "2026-01-01T14:30",
  "flags": []
}
```

예시는 설명용입니다. 실제 구역 정의는 `functions/config/zones.yaml`에서 API의 `floor`와 매핑합니다.

## 날짜별 JSON

```json
{
  "v": 1,
  "date": "2026-01-01",
  "zones": {
    "t1-short-b1": {
      "p": [300, 310, null],
      "c": [520, 520, 520],
      "e": [1]
    }
  }
}
```

위 예시는 배열 앞부분만 보여줍니다. 실제 `p`·`c` 배열은 각각 288칸입니다.

- 인덱스 0 = 00:00, 1 = 00:05, …, 287 = 23:55 KST
- `p`: 주차 대수, `c`: **해당 시점의 운영 면수**. 고정된 설계·기본 면수와 다를 수 있습니다.
- `null`: 아직 수집되지 않았거나 누락되어 메우지 못한 값
- `e`: 수집 누락을 **추정으로 메운 슬롯 인덱스**(없으면 키 생략). `e`에 있는 슬롯의 `p`는 실측이 아닙니다 → [수집 누락 보정](#수집-누락-보정)
- 면수 0: 미운영/닫힌 구역
- 점유율 = `p / c`, 가용 대수 = `max(c - p, 0)`
- `p > c`는 원자료에서 유지합니다. 소비자가 100% 상한 여부를 결정합니다.

성수기 임시 운영·원복 등으로 `c`가 바뀔 수 있습니다. 과거 `c`를 최신 면수나 기본 면수로 덮어쓰지 않습니다. 감소 직후 이미 주차한 차량이 새 운영 면수를 넘으면 `p/c > 100%`와 가용 0대가 동시에 가능합니다.

화면의 [운영 면수 참고](../web/capacity.js)는 기본 면수 설명과 관측된 변경 이벤트를 별도로 관리합니다. T1 단기 지하1층 기본 378대·극성수기 520대 임시 운영·2026-10-13 16:55 원복 설명은 **사용자가 일반 담당자가 아닌 상황실(전화 끝자리 7700)에 문의해 확인한 내용**이며 공항 공개 문서로 확인된 정책표와는 구분합니다. 제공받지 않은 전체 전화번호는 추정하지 않습니다. 이 378대는 `c`를 강제로 대체하는 값이 아닙니다. 다른 변경은 관측 시각·변경 전후 면수만 표시하고 원인을 추정하지 않습니다.

과거 날짜는 확정 후 캐시 1일, 최신값·당일 파일·달력은 캐시 60초입니다. 갱신 주기는 5분이며 모든 구역이 같은 슬롯에 유효한 것은 아닐 수 있습니다.

## 수집 누락 보정

원천 API는 현재 값만 제공하므로 놓친 슬롯은 나중에 다시 가져올 수 없습니다. 수집기는 슬롯(5분) 안에서 먼저 재시도합니다(호출 실패는 2/5/10/20/30초 간격, 응답은 왔지만 원천 `datetm`이 갱신되지 않았거나 구역이 빠진 경우는 20초마다 재조회, 한 슬롯 최대 6회·약 110초). 그래도 비는 슬롯은 아래 조건을 **모두** 만족할 때만 일별 JSON에서 추정으로 메웁니다.

- 같은 구역의 앞뒤 슬롯이 모두 실측이고, 사이의 연속 누락이 **30분(6슬롯) 이하**
- 앞뒤 운영 면수 `c`가 같음(면수 변경·폐쇄 전환은 변경 시각을 알 수 없어 메우지 않음)

값은 앞뒤 실측 `p`를 직선으로 이은 정수 반올림이며 `c`는 앞뒤와 같은 값입니다. 메운 슬롯은 그 구역의 `e`에 인덱스로 남습니다. 수집이 재개되기 전의 끝 구멍, 30분을 넘는 구멍, 날짜 경계를 넘는 구멍은 `null`로 남습니다. 원본(raw/obs)은 바뀌지 않고, 일별 파일을 만들 때마다 같은 규칙으로 다시 계산하므로 수집이 재개되는 순간 앞선 구멍이 자동으로 채워집니다.

과거 날짜는 자정에 확정된 뒤 다시 만들어지지 않으므로, 수집기가 매 수집 때 **현재 보정 규칙 버전(`IMPUTE_VERSION`)으로 만들지 않은 확정 날짜를 최신 날짜부터 최대 3일씩** 다시 발행합니다(진행 상태는 비공개 `state/heal.json`). 이 기능을 처음 배포했거나 규칙을 바꿔 버전을 올리면 과거 전체가 몇 번의 수집 안에 한 번씩 새 규칙으로 갱신됩니다. 같은 일을 직접 하려면 `scripts/republish_days.py`를 사용합니다.

- 화면은 보정값을 색은 그대로 두되 연하게(해칭) 표시하고 툴팁에 "보정값(수집 누락 추정)"을 적습니다. 최고·최저·평균 통계는 실측만 쓰고, 보정 슬롯은 "수집 누락" 개수에 포함해 "보정 N슬롯"으로 따로 표시합니다.
- 예상 모델(IGoTo·연결 방식)은 `e` 슬롯을 학습·기준점으로 쓰지 않습니다.
- `calendar.json`의 날짜 항목에서 최고·평균·누락(`miss`)은 실측 기준이며, 보정한 슬롯 수는 `est`로 따로 제공합니다(없으면 키 생략).
- 외부에서 이 데이터를 사용하는 경우 실측만 필요하면 `e`에 포함된 인덱스의 `p`를 제외하세요.

## calendar.json

- `start`: 수집 시작 날짜
- `days`: 존재하는 날짜와 수집 슬롯 수
- 날짜의 `T1` / `T2`: 최고·평균 점유율, 최고 시각, 누락
- `holidays`: 날짜별 공휴일 이름

존재하는 날짜를 알아내려면 컨테이너 목록을 조회하지 말고 `calendar.json`을 읽으세요. 제공된 Bicep 템플릿은 익명 파일 읽기만 허용하고 컨테이너 목록 조회는 허용하지 않습니다.

## 품질 플래그

`STALE`, `OVER`, `CAPCHANGE`, `GAP`, `CLOSED`, `UNKNOWN_ZONE`, `MISSING`을 기록합니다. 원천 타임스탬프가 갱신되지 않은 슬롯은 실측으로 쓰지 않으며, 짧은 구멍만 [수집 누락 보정](#수집-누락-보정) 규칙으로 메우고 `e`로 구분합니다.

## 외부 재사용

공개 Blob은 파일 URL을 아는 서버/클라이언트에서 인증 없이 다운로드할 수 있습니다. 그러나 브라우저의 교차 출처 `fetch()`는 스토리지 CORS 설정을 따릅니다. 기본 인프라 템플릿은 배포한 웹앱 주소만 허용합니다.

임의 외부 웹앱에 제공하려면 스토리지의 CORS 허용 출처 정책을 별도로 결정해야 합니다. 이 코드의 MIT 라이선스는 원천 공공데이터의 이용 조건·출처 표시 의무를 대신하지 않습니다.

## 데이터 제공자 API

- 주차: `https://apis.data.go.kr/B551177/StatusOfParking/getTrackingParking`
- 승객 예고: `https://apis.data.go.kr/B551177/passgrAnncmt/getPassgrAnncmt`
- 공휴일: `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo`

API 이용 신청, 운영 계정·일일 트래픽, 출처 표시 및 이용 조건은 각 서비스의 공식 안내를 확인하세요. 인증키는 요청 시에만 사용하고 공개 JSON에는 넣지 않습니다.
